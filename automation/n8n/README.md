# n8n (self-hosted Community edition)

The enrichment workflow runs on open-source n8n. The same `compose.yaml` is used locally and on the cloud server; only `.env` differs. Design background: [backend design, "Hosting n8n"](../../docs/backend-design.md#hosting-n8n).

## Local stage

`./start.sh` at the repository root starts the container when `N8N_MODE=local` in the root `.env`. On first run it creates `automation/n8n/.env` from `.env.example` with a fresh `N8N_ENCRYPTION_KEY`. Back that file up: without the key, credentials stored in the `album-n8n_n8n_data` volume cannot be decrypted.

- Editor: <http://localhost:5678>. The first visit asks you to create the **owner** account.
- Health: `curl http://localhost:5678/healthz`
- Logs: `docker logs -f album-n8n`
- `./stop.sh` stops the container but keeps the volume. `docker compose -f automation/n8n/compose.yaml down -v` deletes all n8n data.

## Accounts

Community edition cannot share workflows between users. Only the owner and the user who created a workflow can see it. So:

1. Create the owner account (the team's admin login).
2. In **Settings → Users**, invite a member account for whoever should see the workflow. Without SMTP configured, n8n shows an invite link to copy.
3. Log in as that member and create the enrichment workflow and its Data Table there, so that account owns them.

## Server stage

1. Install Docker on the server and copy this folder together with the local `.env`. Keep the same `N8N_ENCRYPTION_KEY` if you migrate the volume; otherwise export and re-import the workflow.
2. In `.env`, switch to the server block (`N8N_HOST`, `N8N_PROTOCOL=https`, `WEBHOOK_URL`, `N8N_SECURE_COOKIE=true`, `N8N_PROXY_HOPS=1`).
3. Put an HTTPS reverse proxy in front of `127.0.0.1:5678`. A minimal Caddyfile:

   ```text
   n8n.example.com {
       reverse_proxy 127.0.0.1:5678
   }
   ```

4. `docker compose up -d`, create the owner account, then the member account (see **Accounts**), and create an API key while logged in as that member.
5. In the root `.env` of the machine running Album, set `N8N_MODE=remote`, `N8N_BASE_URL=https://n8n.example.com`, and `N8N_API_KEY` to that key, then run `node automation/n8n/deploy.mjs`. It creates the table, credential, and workflow on the server and switches Album's webhook URL and secret. Nothing else in the backend changes.

## Deploying the workflow

```bash
node automation/n8n/deploy.mjs
```

It uses `N8N_BASE_URL` and `N8N_API_KEY` from the root `.env` (create the key in n8n under **Settings → n8n API**), and does the following:

1. Creates the `album_enrichment` Data Table (`key`, `assetId`, `revision`, `caption`, `tags`, `keywords`, `categories`, `wordCount`), or reuses it.
2. Creates or updates the **Album webhook secret** header-auth credential with a new random secret.
3. Creates or updates the **Album enrichment** workflow and publishes it.
4. Saves the webhook URL and secret in Album's settings, so the backend starts sending captions.
5. Runs a smoke test that writes a row, reads it back, and deletes it again.

Running it again is safe. It rotates the secret and redeploys the current workflow definition. For a server whose public address differs from the address used to reach its API, set `N8N_WEBHOOK_BASE` (for example `https://n8n.example.com`). The API key belongs to whoever created it, so the workflow is owned by that account. On the server, use a key from the member account (see **Accounts** above).

### What the workflow does

```text
POST /webhook/album-enrichment        (header X-Album-Secret)
  → Validate and normalize (Code)    tidy caption, dedupe tags, extract keywords, derive categories
  → Valid? ─ no → 422 {error}
  → Build row → Upsert enrichment row (Data Table, key = assetId:revision)
  → Read row back (Data Table get by key)
  → Return enrichment (JSON)

POST /webhook/album-enrichment/purge  (same header)
  → Validate purge → Delete photo rows (Data Table, by assetId) → {deleted}
```

The Code node sources are in `code/`, and the node layout is in `workflow.mjs`. `workflows/album-enrichment.json` is the definition generated by the last deploy (without secrets), for review or manual import.

## Files

- `compose.yaml`: container definition, pinned image version.
- `.env.example`: settings template (the real `.env` is gitignored).
- `workflow.mjs`, `code/`: the workflow definition and its Code node scripts.
- `deploy.mjs`: deploys it through the n8n API and configures Album.
- `workflows/album-enrichment.json`: the last deployed definition.
